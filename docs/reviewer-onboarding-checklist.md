# Reviewer Onboarding Checklist

- [ ] Read the repository's CONTRIBUTING.md before making any changes
- [ ] Pick an open issue, or open a new one describing the change you want to make
- [ ] Create a feature branch with a descriptive name off the default branch
- [ ] Keep commits small and give each one a clear commit message
- [ ] Push the branch and open a pull request into the default branch
- [ ] Write a description that explains what the change does and why
- [ ] Mark the pull request as a draft while it is still work in progress
- [ ] Flip the pull request to ready for review once it is finished
- [ ] Request a review from at least one maintainer
- [ ] Respond to review comments inline and push fixes to the same branch
- [ ] Make sure all automated checks pass before requesting another review
- [ ] Link related issues so the tracker stays up to date
- [ ] Rebase on the default branch if it drifts while you are working
- [ ] Celebrate once the pull request is merged
